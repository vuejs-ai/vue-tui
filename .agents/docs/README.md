# Records map

Open the narrowest record that owns the area being changed. Product direction and durable design live here; exact machine-checkable shapes live in code and tests, and completed plans remain in Git history.

## Product direction

| When changing                                                                                                                | Read                            | Ownership                                                                   |
| ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | --------------------------------------------------------------------------- |
| Product positioning, workloads, what qualifies as product work, priorities, rendering-mode direction, boundaries, or success | [Product intent](./intent.md)   | Authoritative product direction.                                            |
| Current work sequence, near-term focus, or whether an area is currently planned                                              | [Product roadmap](./roadmap.md) | Orders current work without redefining product intent or package contracts. |

## Package boundaries and API design

| When changing                                                               | Read                                                                                                                                                                                       | Ownership                                                                                                                  |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Placement between Runtime, Use, Components, or application                  | [Package architecture](./package-architecture.md)                                                                                                                                          | Owns dependency direction and the test for where reusable behavior belongs.                                                |
| Internal structure of Runtime: units, data structures, entities, boundaries | [Runtime architecture](./architecture.md) and [Architecture decisions](./architecture-decisions.md)                                                                                        | The record owns the target internal structure; the ledger records Yunfei's expressed judgments about it.                   |
| Runtime exports, components, composables, or public types                   | [Runtime API design](./runtime-api-design.md) and [Runtime API decisions](./runtime-api-decisions.md)                                                                                      | Design records the current contract; the ledger records Yunfei's expressed judgments and vouch status.                     |
| `@vue-tui/use` composables or renderless companions                         | [Use API design](./use-api-design.md)                                                                                                                                                      | Owns reusable headless Vue behavior and the root-versus-`/components` split.                                               |
| `@vue-tui/components` membership or API conventions                         | [Components API design](./components-api-design.md) and the relevant [ScrollBox](./components/scroll-box.md), [Spinner](./components/spinner.md), or [Table](./components/table.md) record | Owns the visual component catalog, package-specific admission rule, shared authoring rules, and component-specific design. |
| TSDoc on any first-party public export                                      | [Public API documentation](./public-api-docs.md)                                                                                                                                           | Applies to Runtime, Use, Components, Testing, Vite, and their supported subpaths.                                          |

## Runtime behavior

| When changing                                                                 | Read                                                                                                                                                                                       | Ownership                                                                                           |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| Inline, Fullscreen, non-TTY output, history, resize, or restoration           | [Rendering modes](./rendering-modes.md) and [rendering-mode intent](./intent.md#rendering-modes)                                                                                           | Canonical host and screen-ownership contract.                                                       |
| Renderer layout ownership, provisional geometry, or paint-initiated layout    | [Layout transaction boundary](./rendering-modes.md#layout-transaction-boundary)                                                                                                            | One renderer commit supplies complete inputs and receives only final geometry.                      |
| Input events, stdin ownership, raw mode, or handler delivery                  | [Runtime API design](./runtime-api-design.md#composable-contract) and [accepted input decisions](./runtime-api-decisions.md#useinput-exposes-one-tagged-text-key-and-paste-event-contract) | Runtime owns normalization and terminal demand; public delivery remains broadcast.                  |
| Pointer input, mouse reporting, Fullscreen text selection, or browser hosting | [Architecture decisions](./architecture-decisions.md) and the [open public-shape item](./runtime-api-decisions.md#pointer-input-has-no-exact-public-shape)                                 | Scope, delivery and reporting tiers are decided; nothing is built and no exact public shape exists. |
| Focus, Box metrics, or a composable bound to a rendered component ref         | [Rendered-target design](./runtime-api-design.md#rendered-target-lifetime) and [Runtime API decisions](./runtime-api-decisions.md)                                                         | Vue refs stay public while Runtime privately follows current rendered availability.                 |
| Terminal color, Text measurement, clipping, or a peer behavior comparison     | [Runtime API design](./runtime-api-design.md), [Peer frameworks](./peer-frameworks.md), and [Runtime API decisions](./runtime-api-decisions.md)                                            | Current local contracts decide behavior; peers provide bounded evidence.                            |
