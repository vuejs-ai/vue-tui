# Rendering mode and host behavior matrix

> **Status:** current visual host-behavior evidence with a historical F1 public-projection layer. The supported public live-host selector is only `MountOptions.mode`; render observation and frame scheduling are private implementation concerns, while pointer, semantic caret, selection, and clipboard passages below describe removed historical candidates rather than hidden mechanisms. The internal surface resolver, Inline invariant, application-side escape-hatch requirement, and finite clean-slate mount behavior remain applicable. Screen-reader presentation and every public or private selector for it are removed.

## Why the matrix has more than two rows

Inline and full-screen are the two live terminal screen models. They are not the only rendering surfaces vue-tui currently produces. A redirected stream, `renderToString`, and deterministic observation do not acquire the same surface merely because an application or test requested a mode.

The matrix therefore keeps four questions separate:

1. **Render host:** live process, deterministic test, or synchronous string render.
2. **Requested mode:** inline or full-screen, when the host accepts a terminal-mode request.
3. **Effective surface:** main-screen live region, alternate-screen viewport, final stream output, static string, or test observation.
4. **Independent I/O facts:** Runtime's private output-cadence policy, stdout and stdin TTY state, and terminal protocol availability.

This matrix is the source behavior model rather than a public type definition. The internal resolver still maps these axes into one coherent session, but applications do not receive that whole graph. The current Path 1 projection exposes coherent numeric root-layout `width` and `height` refs through `useLayoutSize()`.

## Current public resolution and private surface mechanics

The live renderer now validates and resolves one surface before reserving stdout or mutating terminal state. [`render-session.ts`](../../packages/runtime/src/render-session.ts) owns the pure resolution; [`render.ts`](../../packages/runtime/src/render.ts) consumes its result:

```ts
requestedMode = normalize(publicOptions.mode ?? "inline");
dimensions = resolvePositiveStdoutSizeOrProvenanceAwareTerminalProbe();
surface = resolveLiveSurface({ requestedMode, stdout, terminalProbe });
alternateScreen = surface.kind === "fullscreen-terminal";
```

Surface kind is decided by host facts alone: TTY stdout is always a live surface and non-TTY stdout is always the document final-stream host, for either requested mode. The former mouse, hit-testing, selection, and clipboard experiments do not add surface inputs or retained capabilities. Their implementations were removed; only their explicitly historical records remain as evidence for evaluating a future concrete application need.

Box-rooted `v-show` also does not add a surface-resolution branch. Vue's directive writes the Box host's minimal `style.display` facade, which composes with the latest authored Box `display` value and updates Yoga. Both visual modes then derive layout, paint, focus eligibility, and Box size from the same effective `DISPLAY_NONE` state. The subtree remains mounted and reactive. Text and context-dependent virtual Text do not expose that layout seam. Static exposes only a no-op display facade so direct `v-show` remains operational without changing its mounted history eligibility.

The supported `mode` option accepts only `"inline"`, `"fullscreen"`, or `undefined`; omission becomes an Inline request. Own `fullscreen`, `alternateScreen`, `interactive`, `debug`, or `liveUpdates` keys fail synchronously, including when their value is `undefined`. The retained repository-only controls — render observation, scheduling, Kitty negotiation, terminal-size probing, and suspension hosting — associate with an otherwise ordinary public-options object through module-private state, and the public testing bridge invokes the original Runtime-owned mount path without exposing that association to a caller-owned `mount` wrapper. Every hidden or superseded string is rejected before stream getters, stdout ownership, terminal probing, raw mode, listeners, Vue setup, or terminal writes.

Output cadence follows the resolved surface: live TTY surfaces update continuously, and the non-TTY document host is final-only; neither states whether the application can receive input. Runtime records requested and effective mode, output, and coherent dimensions in its private session. Public components receive only the coherent root-layout width and height they can act on; `useInput()` and `useStdin()` provide the separately reviewed input contracts.

Terminal dimensions carry provenance. A complete positive stdout pair wins. If it is incomplete, one complete positive pair from process stdout/stderr, `COLUMNS`/`LINES`, a controlling-terminal ioctl, `tput`, or Linux `resize` replaces it atomically; fields from two sources are never spliced into a claimed viewport. Process-global fallback is used only for the process's own stdout/stderr, not an arbitrary custom TTY. Probe failure returns unavailable instead of manufacturing `80×24`. A valid partial width may still inform an unbounded private layout, but it cannot acquire a visual terminal mode. Public hosts expose the dimensions Runtime actually applies through `useLayoutSize()`; explicit string rendering alone may select `height: Infinity`.

## Current private live-host matrix

These rows are exhaustive for the axes that select a rendering surface. Stdin behavior remains an independent modifier covered immediately afterward; deterministic commit observation is orthogonal to surface selection.

| ID  | stdout  | Requested mode | Current effective surface                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --- | ------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | Non-TTY | Either         | **Final-stream document host.** Modeled 80×24 layout; new `@vue-tui/runtime/inline` `Static` output is written as it appears and only the latest dynamic frame is written at teardown. Reason is `stdout-not-tty`.                                                                                                                                                                                                                                  |
| L5  | TTY     | Inline         | **Bounded Inline live region.** Relative main-screen updates; with usable terminal dimensions, layout rows equal terminal rows as a maximum rather than a fixed height. Without usable dimensions the modeled 80×24 layout applies and the surface stays live. Paint is hard-clipped to the terminal and the origin remains unstable.                                                                                                               |
| L6  | TTY     | Full-screen    | **Fixed full-screen viewport.** Requires positive terminal dimensions and otherwise fails before setup or terminal mutation. Alternate screen, exact terminal-sized layout, origin `(0, 0)`, clipping, automatic absolute changed-row replacement after a valid baseline, and full repaint at lifecycle or uncertain-output boundaries. The presence of `Static`, including an empty region, is rejected before its output or a new viewport frame. |

The supported public mount derives its row from stdout capabilities, usable dimensions, and requested mode: non-TTY output maps to F1 and TTY output maps to L5-L6. No supported option adds another presentation axis.

`Static` is the accepted `@vue-tui/runtime/inline` terminal-history primitive. One mounted instance commits one ordinary slot tree once; Vue iteration and stable keys own collections, and remounting begins a separate history block. An output-free eligible transaction leaves the instance open, while ancestor or direct `v-show` does not change eligibility. Several blocks accepted together use current rendered host-tree order, and later eligibility only appends. On the Fullscreen surface, rejection happens before Static bytes, dynamic output, observation, or a new frame. Unsupported placement and nesting plus exact Static-specific diagnostics, recovery, and failure timing remain implementation behavior rather than public host axes.

### Observation and scheduling

Deterministic commit observation uses an internal render observer that receives structured `{ dynamic, staticOutput }` content independently from terminal bytes. Installing the observer does not select a host, change update cadence, append frames to stdout, or manufacture a capability. Internal tests may select unthrottled scheduling, but `maxFps` is not a supported public mount option. The former `debug` mount option is removed and fails synchronously before stream inspection or terminal mutation; `@vue-tui/testing` exposes supported observation through `RenderResult` instead.

### Development-reload modifier

An in-place Vue hot update keeps the mounted session and repaints through its existing surface. A Vite full reload runs the registered internal teardown before replacing the app, restoring terminal modes and the alternate screen without settling the old app's exit promise; the newly imported app then acquires its surface again. The target keeps that distinction: a hot update preserves the session, while a full reload must completely release and reacquire terminal ownership.

### Input

stdin is independent of the output surface. `useInput()` requests Runtime-managed normalized input and requires a controllable TTY input stream; `useStdin()` returns the selected raw stream and can hold raw mode independently. Inline, Fullscreen, and final-output rendering do not add mouse, hit-testing, selection, or clipboard behavior.

Static rejection follows the fatal path: restore exact acquired ownership first, then write a sanitized stack or message to stderr. Fatal teardown otherwise has the same ordering.    |

Mount acquisition, suspension, continuation, repaint, and teardown are exception-safe lifecycle transactions. Listener registration precedes terminal acquisition; a partial mount rolls back every resource acquired so far. Normal unmount, app exit, process exit, `beforeExit`, SIGINT, SIGTERM, SIGHUP, Runtime failure, and full HMR reload release only owned raw mode, bracketed paste, Kitty keyboard state, cursor state, alternate screen, listeners, and stream reservation. Cleanup continues when one release throws. An ordinary teardown or settlement re-entered from a nested stream write is deferred until the current acquisition or repaint has finished and every resource can receive its release turn. A non-returning `process.exit()` or signal-exit callback is the exception: it performs immediate synchronous restoration, skips final user rendering and Vue lifecycle hooks, and returns control to Node only after owned terminal state has been released. A second live app on the same stdout throws synchronously before mutation and may retry after the owner releases it. Direct process-stream writes bypass coordination; default console protection uses one global patch whose active-app stack routes each intercepted record through the current owner's coordinated output.

## Historical F1 record

The earlier F1 design, its then-current accepted mount contract, input-validation and host tables, target lifecycle, finite session facts, Inline-overflow PTY comparison, and evidence list were removed from this file on 2026-07-25 and remain in git history. They were implementation evidence, not a current API or hidden feature contract: their screen-reader rows, `presentation` facts, and transcript helpers were superseded and removed on 2026-07-22; the `liveUpdates` cadence override and the `incrementalRendering` test control were later removed entirely; and the `ErrorOverview` fatal-error policy was superseded by Vue-native component-error flow. Current behavior is defined by the sections above and the [Runtime public API decision ledger](./runtime-public-api-decisions.md).
